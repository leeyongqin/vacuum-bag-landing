## 1. 现状诊断

以下每一条都基于在 390×844（iPhone 14/15 视口）和 1280×900 下的真实渲染测量，不是观感描述。

### 1.1 落地页 —— 核心问题是「表单太靠下」

现版的页面顺序是：`hero → 权益清单 → 三步流程 → 表单`。也就是说，**买家必须滚过两屏营销文案才能摸到第一个输入框**。而这些买家是从包裹卡片上的二维码扫进来的，意图极其明确——「我要激活保修」，不是来读文案的。

实测（390×844）：

| 关键元素 | 现版位置 | 首屏（844px）内？ |
|---|---|---|
| 邮箱输入框 | y = 933 | ✗ 需滚动 132px |
| 订单后 4 位输入框 | y = 1011 | ✗ |
| **主 CTA 按钮** | **y = 1138 – 1185** | **✗ 需滚动 341px** |
| 页面总高 | 1637px | — |

**这是本次重设计要解决的第一问题。** 新版把这些元素整体上移：

| 关键元素 | 新版位置 | 变化 |
|---|---|---|
| 邮箱输入框 | y = 488 | ↑ 445px |
| 主 CTA 按钮 | y = 783 – 837 | **↑ 355px，完整进入首屏** |
| 注册成功后折扣码 | y = 341 – 584 | **进入首屏**（现版需滚动） |

**次要问题：**

| # | 问题 | 严重度 | 位置 |
|---|------|--------|------|
| L1 | 6 个语言按钮做成顶部横向滚动条，是页面**第一个**被看到的东西，像调试控件而不是产品 | 中 | `.lang-bar` |
| L2 | 信任条用 emoji（🔒🛡️✉️）而 hero 用 SVG 盾牌，**同一页面两套图标语言**；emoji 在 Windows/Android 上字形差异大，显得业余 | 中 | `.trust-bar` |
| L3 | 表单标签全大写：`LETZTE 4 ZIFFERN DER BESTELLNUMMER` 共 33 字符，在 480px 宽度下折成两行且极难扫读（德/法标签尤其长） | 中 | `.f-label` |
| L4 | 错误提示靠 `margin-top: -10px` 负边距硬拽位置，且用 `display:none` 切换 —— 屏幕阅读器完全读不到 | 高 | `.f-err` |
| L5 | 页面无「我在第几步」的进度感，也无粘性 CTA | 低 | — |
| L6 | 权益清单（3 条长句）与三步流程（3 条带描述）**在讲同一件事**，重复占掉近一屏 | 中 | `.value-wrap` / `.steps-wrap` |

### 1.2 统计面板

| # | 问题 | 严重度 | 证据 |
|---|------|--------|------|
| D1 | **移动端横向溢出**。表格无任何响应式规则，5 列真实数据在 390px 视口下把文档撑到 **454px**，长邮箱折成 3 行，行高从 40px 涨到 **73px** | 高 | 实测 `docScrollWidth 454 > 390` |
| D2 | **README 声称的能力并不存在**。README 写「面板『营销同意』列可直接筛出这批人」，但面板里**唯一的输入控件是密码框**，没有任何筛选 UI | 高（文档与实现不符） | 实测 `hasConsentFilter: false` |
| D3 | 「复制 N 个邮箱」按钮用 `float: right` 浮在表格**上方**，与表格没有视觉关联；且它永远复制**全部**记录，无法只导出筛选后的人 | 中 | 实测 `float: right` |
| D4 | 刷新按钮同样用 `float: right`，布局脆弱 | 低 | — |
| D5 | 「已同意 / 未同意」都是高饱和徽章，视觉权重相同，卖家扫表格分不出重点 | 中 | `.badge-green` / `.badge-blue` |
| D6 | 转化率徽章配色阈值（`>= 3%`）硬编码在 JS 里，界面上没有任何说明，看数据的人不知道 3% 从哪来 | 低 | `dashboard.html:194` |
| D7 | 无加载态、无空状态。首次打开或 KV 为空时只有一行灰字，看不出是「没数据」还是「加载失败」 | 中 | `.empty-hint` |
| D8 | 复制失败降级到 `window.prompt()`，弹系统对话框，体验断裂 | 低 | `dashboard.html:121` |

### 1.3 无障碍与合规（实测）

这是本次改动里**不能商量**的部分 —— 站点面向德国等欧盟市场，GDPR 声明的可读性是合规问题，不只是审美问题。

| 检查项 | 标准 | 现版实测 | 判定 | 新版 |
|--------|------|----------|------|------|
| GDPR 声明文字对比度 | ≥ 4.5:1 | `#9a958f` on `#f7f5f0` = **2.73:1**，字号仅 11px | **✗ 不合规** | `#6b6560` = **5.27:1** |
| 语言按钮触摸目标 | ≥ 44×44px | **32×61px** | **✗** | 40px 高 + 语言抽屉 52px 行高 |
| 输入框字号 | ≥ 16px（iOS 免缩放） | **15px** | **✗** iOS 聚焦会强制放大整页 | 16px |
| 错误信息可播报 | 4.1.3 | `display:none` 切换，无 `role`/`aria-live` | **✗** | `role="alert"` |
| 焦点可见 | 2.4.7 | 仅 `border-color` 变色，几乎不可见 | **✗** | 3px 外发光环 + `:focus-visible` |
| 状态语义 | 4.1.2 | 语言按钮无 `aria-pressed` / `aria-current` | **✗** | 已补 |
| 动效偏好 | 2.3.3 | 无处理 | **✗** | 全部包进 `prefers-reduced-motion` |

## 2. 设计原则

这次重设计只围绕四条原则，凡是与之冲突的装饰都砍掉：

**① 意图优先，文案靠后。**
买家是带着明确任务来的。把表单顶到首屏，营销内容降级为表单下方的支撑信息。文案不是删除，是**降权**。

**② 一个页面只有一套视觉语言。**
图标要么全是 SVG 线性，要么全是 emoji。信任条与 hero 统一为 1.6px 描边的线性 SVG。

**③ 状态必须可见。**
聚焦、通过、失败、加载、空——五种状态都要有明确的视觉表达。用户不应该猜「刚才那下点上了没有」。

**④ 数据界面为「扫读」设计，不为「完整」设计。**
卖家打开面板是为了找两类人：**同意营销的**（要跟进）和**没同意的**（要区分对待）。一切布局服务于这个动作。

## 3. 设计系统（摘要）

完整规范见 `design-system.html`。这里只列关键决策。

### 色彩
保留原品牌 `navy #1a2e4a` + `gold #c8a84b`，但把原来「3 个孤立色值」扩展为完整色阶（navy 950→50、gold 800→50、warm ink 900→50），并建立**语义别名层**。组件代码只允许写 `--text-muted` 这类语义 token，不直接写色阶 —— 这样日后整改对比度、加暗色模式都只改一处。

**主 CTA 保留「gold 底 + navy 文字」**，这是现版做对了的地方：`#fff on #c8a84b` 只有 2.1:1 完全不可读，现版用深蓝文字是对的，继承。

### 字体
不引入任何 Web Font（项目零依赖约束）。三处关键改动：

1. **输入框 15px → 16px** —— 消除 iOS 聚焦自动缩放
2. **表单标签全大写 → 句首大写** —— 德语标签 33 字符全大写折两行，扫读成本极高
3. **数据表启用 `font-variant-numeric: tabular-nums`** —— 31px 的数字列必须等宽，否则表格里左右跳动

### 间距
原版间距是手写散值（22 / 26 / 30 / 18px…），无法推导。收敛到 **4px 基数**：控件内边距 12–16，卡片内边距 20–24，区块间距 40–64。

### 圆角与阴影
控件 `12`，卡片 `16`，徽章 `999`（原版统一 10px 让输入框和卡片一样平，缺少层次）。
阴影分 4 级：越靠近用户操作焦点抬得越高。原版所有区块靠 `border-bottom: 1px` 一条条横线切分，视觉上是「堆叠的纸片」，没有主次。

### 动效
`120ms`（无感操作）/ `180ms`（默认）/ `300ms`（需要被感知的转场），全局单条缓动 `cubic-bezier(.2,.7,.3,1)`。**全部包进 `prefers-reduced-motion`** —— 前庭功能敏感的用户会因成功页的打勾动画不适。

## 4. 落地页改造方案

### 结构对比

```
现版                              新版
─────────────────────────────     ─────────────────────────────
语言滚动条（6 个按钮）             粘性顶栏：品牌 + 语言入口
Hero（标题 + 副标题）             Hero（标题 + 副标题 + 3 枚权益 chip）
权益清单（3 条长句）      ┐        ┌ 主表单卡（上浮压住 hero）
三步流程（3 条带描述）    ┘ 重复     │   邮箱 / 订单后 4 位 / 同意 / CTA
表单（邮箱 / 订单 / 同意 / CTA）    └ GDPR 声明
Tips 卡片                         信任条（3 个线性 SVG 图标）
信任条（emoji）                   三步流程（纵向连接线）
页脚                              常见问题（3 条折叠，零 JS）
                                  页脚
```

**权益清单与三步流程合并**：原来的「权益清单」压缩成 hero 里的 3 枚 chip（`12 Monate Garantie` / `Kostenloser Ersatz` / `Exklusiver Rabatt`），「三步流程」保留在表单下方作为补充说明。省下近一屏。

### 关键组件设计

**① 粘性顶栏 + 语言抽屉**
品牌与语言入口常驻顶部。语言不再是横排 6 个按钮，而是一个 `🌐 DE ⌄` 触发器，点开是底部抽屉：每个语言显示**母语名称**（Deutsch / Français / Italiano…）而非仅国家代码，当前语言高亮 + 打勾。行高 52px，达标触摸目标。

**② 表单卡**
白卡圆角 22px + 大阴影，`margin-top: -64px` 上浮压住 hero —— 这个重叠既制造层次，也把表单物理上提进首屏。

- 字段前置线性图标（信封 / 单据），聚焦时图标由灰转 navy
- 订单后 4 位用**等宽字体 + 0.28em 字距**，视觉上就是「四个数字格子」；输入时自动剔除非数字并截断到 4 位
- 通过校验后输入框右侧淡入绿色对勾（即时正反馈）
- 订单号字段下方挂一个原生 `<details>` 折叠提示「Wo finde ich die letzten 4 Ziffern?」—— 默认收起不占高度，需要时展开，**零 JS**
- CTA 带加载态：文字切换为「Wird aktiviert…」+ 旋转指示器，同时禁用防重复提交

**③ 成功态**
现版的成功态是在原位置 `display:none/flex` 切换，用户会被弹回页面顶部，然后要滚过整个 hero 才能看到折扣码。

新版让成功态**自带深色头图**（打勾动画 + 标题 + 说明），并隐藏 hero。实测折扣码落在 **y = 341–584**，完整进入首屏。折扣码做成**票券样式**（两侧半圆缺口 + 金色虚线边框 + 等宽大字），复制后弹 toast 反馈而不是把按钮文字改掉再改回来。

**④ 信任条与 FAQ**
信任条换成 1.6px 描边的线性 SVG（锁 / 盾牌 / 信封），与 hero 盾牌同一套语言。
原「Gut zu wissen」的 3 条 tips 改为折叠面板（原生 `<details>`），默认收起，页面更短。

## 5. 统计面板改造方案

### 结构对比

```
现版                              新版
─────────────────────────────     ─────────────────────────────
居中登录框                        登录卡（密码可见性切换 + 记住密钥）
float:right 刷新按钮              侧栏导航（概览 / 注册明细 / 每日明细）
4 张 KPI 卡                       粘性顶栏（标题 + 时间范围 + 刷新）
语言胶囊列表（横向挤成一堆）       KPI 卡 ×4（含迷你趋势线）
注册明细表                        ├ 语言分布（横向条形图 + 百分比）
每日明细表                        ├ 注册明细（搜索 + 筛选 + 排序 + 导出）
                                  └ 每日明细（分布条 + 合计行）
```

### 关键改动

**① 三视图导航**
侧栏（≤1000px 折叠为两行式头部：品牌 + 退出，下方三个等宽标签页）切换「概览 / 注册明细 / 每日明细」。当前标签 `aria-current="page"` 高亮。

> 移动端头部**必须换行**。实测单行横排会把「退出」挤出 390px 可视区，用户无法登出。

**② KPI 卡 + 迷你趋势线**
4 张卡：总浏览量 / 表单提交 / 转化率 / 获客总量。前两张内嵌由每日数据实时生成的 SVG 折线（不造假数据 —— 页面里没有「较上期 +12%」这类无源指标）。
「获客总量」是**累计去重值，不随时间窗变化**，所以单独用深色卡强调，并在副标题里写明「不受时间窗影响」——现版把它和其它窗口内指标并排，容易被误读。

**③ 语言分布：从胶囊改为条形图**
现版把 6 个语言挤成一排胶囊（`德语: 2090 (61%)`），无法一眼比出量级。新版改为横向条形图：语言名 + 按最大值的比例条 + 绝对数 + 占比。德国站 61% 的压倒性占比一眼可见。

**④ 注册明细表（本次最实质的功能补强）**

新增工具条，修掉 D2/D3：

- **搜索框** —— 按邮箱或订单后 4 位实时过滤
- **营销同意筛选 chip** —— `全部 16 / 已同意 11 / 未同意 5`，把 README 声称却不存在的能力真正做出来
- **可排序表头** —— 点击任意列头切换升/降序，`aria-sort` 同步
- **「复制 N 个邮箱」只复制当前筛选结果** —— 这是 D3 的关键修复。按钮文字随筛选实时变化（`复制 11 个邮箱`），杜绝「以为复制了全部，其实只复制了筛选后的」这类事故
- **CSV 导出** —— 带 BOM，Excel 打开中文不乱码
- **单行复制** —— 每行尾部一个复制按钮，复制单个邮箱
- **邮箱为 `mailto:` 链接** —— 点击直接唤起邮件客户端
- **未同意徽章降为灰底** —— 只让需要行动的那一列跳出来

**⑤ 响应式：表格转卡片**
≤760px 时 `thead` 隐藏，每行 `tr` 变成独立卡片，每个 `td` 用 `::before { content: attr(data-label) }` 显示字段名。

实测对比：

| 指标 | 现版 | 新版 |
|---|---|---|
| 390px 视口文档宽度 | **454px（横向溢出）** | 375px（无溢出） |
| 长邮箱所在行行高 | **73px（折 3 行）** | 卡片化，字段各占一行 |

**⑥ 状态补全**
- **加载骨架** —— 刷新时 KPI 卡、语言条、表格显示 shimmer 占位，让「正在加载」可见
- **空状态** —— 有图标 + 标题 + 可操作的建议（「换个时间范围试试，或确认落地页已正常上线」），区分「真的没数据」和「加载失败」
- **筛选无结果** —— 单独文案「调整搜索关键词或切换筛选条件后重试」，与「本就没有记录」区分

**⑦ 转化率阈值可见化**
把硬编码的 3% 目标线写进界面说明文字，并让徽章配色与之对应。

## 6. 无障碍验收清单

落地时必须逐条通过：

- [ ] 所有正文 / 小字对比度 ≥ 4.5:1（`--text-muted` 是下限，`--text-faint` 不得用于需要阅读的文字）
- [ ] 所有可点击元素触摸目标 ≥ 44×44px
- [ ] 所有交互元素有可见的 `:focus-visible` 焦点环
- [ ] 表单错误有 `role="alert"`，屏幕阅读器可播报
- [ ] 语言切换按钮有 `aria-pressed` / `aria-current`
- [ ] 输入框字号 ≥ 16px（iOS 不缩放）
- [ ] 所有动效在 `prefers-reduced-motion: reduce` 下降级
- [ ] 表格 `<th>` 有 `scope`，排序列有 `aria-sort`
- [ ] 键盘可完整操作：Tab 遍历、Enter 提交、Esc 关闭抽屉
- [ ] 图片 / 图标有 `aria-hidden` 或替代文本

## 7. 落地路径

原型是**独立可评审的设计稿**，不是可以直接覆盖生产的代码。迁移时按下列顺序做，每一步都可独立部署验证。

### 第 1 步：设计系统落地（低风险）
把 `design-system.html` 里的 `:root` token 块复制进 `public/index.html` 和 `public/dashboard.html` 的 `<style>` 顶部，把现有硬编码色值替换为语义 token。
**这一步不改任何布局**，但立刻修掉对比度合规问题（1.3 表格前两行）。
验证：`grep -c '#9a958f' public/*.html` 应为 0。

### 第 2 步：落地页布局重排（中风险，核心收益）
按第 4 节重排 DOM 顺序：合并权益清单与三步流程 → 表单上浮进首屏。
保留现有 `CONFIG` 与 `L` 字典结构不变，只新增文案键（`cardTitle` / `cardSub` / `orderHelpTitle` / `orderHelpText` / `c1`–`c3` / `faq1q`–`faq3q` / `sheetTitle` / `okSaved`），原型里 6 语言的新文案可直接取用。
**`CONFIG.promoCode` 保持留空逻辑不变** —— 原型为了展示票券设计填了示例码 `AROME12`，生产环境留空即自动隐藏整个折扣模块。
验证：390×844 下 CTA 按钮 `getBoundingClientRect().bottom ≤ 844`。

## 8. 待确认项
