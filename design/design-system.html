色彩 Color

保留原品牌 navy + gold 的信任感与品质感，把原来「3 个孤立色值」扩展为可用的完整色阶，并补上语义别名。每个色块下方实时计算与白底 / 页面底色的对比度，标红的即为不可用于正文的色值。

品牌主色 · Navy（信任 / 权威 / 主体结构）

品牌辅色 · Gold（行动 / 稀缺 / 奖励）

中性色 · Warm Ink（文字 / 描边 / 分隔）

语义别名 —— 写界面时只用这一层

组件代码里不允许直接写 --navy-700 这类原始色阶，必须走语义别名。这样换肤、暗色模式、对比度整改都只改一处。

--bg#f6f4ef页面底色（暖米白，替代原 --cream）

--border#e2ddd3常规描边
--border-strong#cfc8bb需要更明确边界的控件（次级按钮）
--text#171614标题
--text-body#3d3a36正文

--gold-500#c8a84b主行动按钮底色（配 navy 文字）
对比度整改（必做）
原版把 GDPR 声明、页脚、小节标签等 11px 小字 染成 #9a958f，在米白底上对比度仅 2.7:1，远低于 WCAG AA 要求的 4.5:1。新版统一收到 --text-muted（5.3:1）。这不是审美问题，是欧盟站点可访问性合规问题。

字体 Typography

不引入任何 Web Font —— 项目约束是零依赖、可直接部署。使用系统字体栈，在 iOS / Android / Windows 上都是各自平台最清晰的那套字形，且德语长单词不会因字体度量差异而破版。

三处字体改动，每一处都在解决问题
① 输入框字号 15px → 16px。iOS Safari 在聚焦字号小于 16px 的输入框时会强制放大整个页面，用户填完邮箱会发现页面被放大、需要手动缩回去 —— 原版正是 15px。
② 表单标签从全大写改为句首大写。原版标签是 LETZTE 4 ZIFFERN DER BESTELLNUMMER，33 个字符的全大写 + 字距，在 480px 宽屏上折成两行且极难扫读。德语 / 法语标签尤其长。
③ 数据表启用 font-variant-numeric: tabular-nums。统计面板的数字列必须等宽对齐，否则 32px 的数字在表格里会左右跳动。

间距 · 圆角 · 阴影 Space / Radius / Elevation

间距阶（4px 基数）

原版间距是散落的手写值（22px / 26px / 30px / 18px …），无法推导。收敛到 4 的倍数后，任意两块间距都有依据。

Token值典型用途
--sp-1 ~ --sp-34 / 8 / 12图标与文字、标签与输入框、徽章内边距
--sp-4 ~ --sp-516 / 20卡片内边距、字段之间的垂直间距
--sp-6 ~ --sp-824 / 32页面左右安全边距、卡片间距
--sp-10 ~ --sp-1640 / 48 / 64区块之间、桌面端页面留白

阴影 · 用高度代替描边

原版所有区块靠 border-bottom: 1px 一条条横线切分，视觉上是「堆叠的纸片」，没有主次。新版改用阴影分层：越靠近用户操作焦点的元素，抬得越高。

动效 Motion

动效只服务于两件事：告诉用户发生了什么（状态变化）与把注意力引到下一步（焦点引导）。不做装饰性动画。

Token时长用在哪儿
--t-fast120ms按钮按下、hover 变色、图标旋转 —— 必须「无感」
--t-base180ms输入框聚焦环、折叠面板展开、徽章切换 —— 默认时长
--t-slow300ms抽屉 / 浮层进出、成功态接管 —— 需要被感知的转场
--easecubic-bezier(.2,.7,.3,1)全局唯一缓动曲线。快进慢出，符合物理直觉
强制要求：所有动效必须包在 @media (prefers-reduced-motion: no-preference) 内，或在 reduce 时降为 0.01ms。前庭功能敏感的用户会因成功页的「打勾放大 + 上浮」动画产生不适。

组件 Components

下面是两个原型页面实际使用的组件全集。每个组件都已内置 hover / focus-visible / disabled / 错误态。

按钮 · Button

主行动按钮 = gold 底 + navy 文字。金色在深蓝页面上是最亮的元素，天然成为视觉焦点；用 navy 而非白色文字是因为 #fff on #c8a84b 只有 2.1:1，完全不可读 —— 原版用对了这一点，保留。

输入框 · Field（含四种状态）
默认态：描边 + 前置图标
聚焦态：描边转 navy + 3px 外发光环
Bitte gültige E-Mail-Adresse eingeben
通过态：绿描边 + 尾部对勾，即时正反馈
徽章 · Badge
已同意 未同意 新客 复购 失败

原版把「未同意」也做成蓝色高亮徽章，视觉权重和「已同意」一样重，卖家扫一眼表格分不出重点。未同意 = 灰底弱化，只让需要行动的那一列跳出来。

无障碍红线 Accessibility Guardrails

这几条是「不满足就不算交付」的硬性约束，两个原型都已实现。目标：WCAG 2.1 AA。

规则标准原版问题 → 新版做法
正文对比度≥ 4.5:1小字用了 #9a958f（2.7:1）→ 全部收到 --text-muted（5.3:1）
触摸目标≥ 44×44px语言按钮 padding:5px 12px 实际高度约 26px → 提到 44px
焦点可见2.4.7仅靠 border-color 变色，键盘用户几乎看不见 → 加 3px 外发光环 + :focus-visible
错误播报4.1.3错误文字直接 display:none，屏幕阅读器读不到 → role="alert" + aria-live
状态语义4.1.2语言按钮无选中语义 → aria-pressed / aria-current
表单可辨识1.3.1标签用 for 关联是对的，保留；补充 aria-describedby 指向提示与错误文案
输入缩放1.4.4输入框 15px 触发 iOS 自动缩放 → 提到 16px
动效偏好2.3.3无处理 → 全部动效包进 prefers-reduced-motion
